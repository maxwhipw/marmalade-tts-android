The problem

On the shipped A3 card the badge is a small pill placed inline in a Row after the engine name (OnboardingScreen.RecommendedTag). The name column has weight(1f), so "Kitten Nano (v0.8)" claims its full width and the pill is squeezed into whatever is left — a sliver about one glyph wide. Compose then wraps the pill's text character-by-character, and "RECOMMENDED" renders as a vertical strip of letters down the middle of the card. The fix is a layout that gives the badge a home which can't be crushed. Every option below is rendered in the real card so prominence can be judged against a neighbouring (non-recommended) card.

Today — the vertical-letters bug

Faithful reproduction: the pill is given the ~1-glyph width it collapses to in Compose, so the char-wrap is visible. This is exactly what the screenshot shows on the Kitten card.

R1

Its own line

Smallest change, zero risk. Name on line one; the pill drops to a line of its own directly beneath it, left-aligned above the tagline. It can never be crushed because nothing competes for the width. Reads as "Kitten Nano · Recommended".

For

One-line diff (move the pill out of the name Row). Robust for any name length or locale. Keeps the badge quiet and close to the name.

Against

Adds a little vertical height to the recommended card; the badge is the least prominent of the options — easy to miss on a quick scan.

R2

Eyebrow above the name

A kicker line. A tiny "★ RECOMMENDED" overline sits above the name like a section eyebrow, optionally with a hairline rule trailing it. The eye hits the endorsement first, then the name.

For

Clear editorial hierarchy — the recommendation reads before the name, which is what you want on a "which one?" screen. Still uncrushable, still compact.

Against

An overline above a card title is a slightly unusual pattern for Material; needs the star or rule to not look like a stray label.

R3

Corner tab

Card-level, not name-level. A small toast-coloured tab tucked into the card's top-left corner (rounded into the card), the row content starting below it. The badge decorates the card, so name length is irrelevant.

For

Distinctly marks the whole card as special without touching the name row. Playful, on-brand, and impossible to crush. Good glance-value.

Against

More chrome; the tab competes a little with the checkbox for the top-left. Needs the selected-card wash to not clash with the tab colour.

R4

Full-width header strip

Loudest. A slim "★ RECOMMENDED" bar spans the full top of the card; the normal row sits under it. Unmistakable, and the strongest separation between the recommended engine and the rest.

For

Maximum prominence — the recommended card is obvious from across the room. Perfectly stable regardless of name or locale.

Against

Heaviest option; can feel like a store "BEST SELLER" banner. Uses a full band of toast colour, so it must stay subtle to keep orange precious.

R5

Inline, name-priority

Keep it on the name line, fix the crush. The pill keeps its natural width and the name yields — it takes weight(1f) and ellipsizes if it must. In practice these three names all fit, so it looks like the original intent, minus the bug.

For

Closest to the original design; no extra height. Correct one-line fix: swap which element owns the flexible width.

Against

A long name in another locale would truncate the name rather than the badge — arguably the wrong thing to sacrifice. Tight on a 400dp frame with the spec column.

Notes for review

  • The bug is a layout ordering issue, not a colour one. Any option that stops the name Row from starving the pill fixes it: give the badge its own line/row (R1–R4) or make the name the flexible element instead of the badge (R5).
  • Prominence ladder: R1 (quietest) → R2 → R3 → R4 (loudest). Since only one engine is ever recommended, a louder mark is defensible, but it spends toast colour — keep the accent orange for the Install CTA per marmalade-design-scheme-v0.
  • Same badge, two homes. Whatever wins must also work on the Engines tab card (EnginesScreen.EngineCard), which shares EngineSpecColumn. R1/R2/R5 port for free; R3/R4 need the card to own the corner/top (also fine there).
  • Case + star (the case section) are orthogonal to placement — decide them once and apply to the winner. All-caps is louder and matches the current string; title case is softer and more on-brand-friendly.
  • Dark mode. The pill uses the toast container (tertiaryContainer) in both modes; there is no orange on the dark frame. Check the strip (R4) isn't too bright on dark.
  • Fonts. System grotesque (no CDN). Wordmark styled, not Momo Trust Display.
