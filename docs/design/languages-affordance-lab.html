The problem

Kokoro's Languages value is "9 languages" followed by a 16 dp ⓘ on the right, the whole thing a clickable Row with only 2 dp horizontal / 4 dp vertical padding (EngineLanguagesValue). Two faults: the touch target is well under the 48 dp minimum, and nothing signals it's tappable — bold text plus a faint grey glyph reads as decoration. Max's steer: put the icon on the left, and make the affordance obvious. Each option below sits in the real 118 dp spec column; the dashed box marks the actual tap area.

= touch target outline (lab-only overlay, not shipped). Aim: the dashed box should reach a comfortable ~44–48 dp tall.

Today — icon right, sliver target

The shipped affordance. The tap box barely clears the text; the ⓘ is small, grey, and to the right of the words, so the eye reads "9 languages" as a plain stat.

L1

Icon on the left, roomy target

Max's suggestion, done properly. The ⓘ leads the value ("ⓘ 9 languages") and the whole Row gets real padding (negative margin so the ink stays put but the touch box grows to ~44 dp). Leading-icon is the standard "there's more here" cue.

For

Minimal visual change, honours the ask, and fixes the target size. A leading icon is a familiar "expandable / info" pattern.

Against

A bold value with a quiet leading glyph can still read as decorative; the icon alone doesn't scream "button" the way a link or chip does.

L2

Underlined link

Loudest "tap me" with the least chrome. "9 languages" is styled as a text link — toast-tinted and underlined — with the ⓘ leading. Underline is the most universally understood tappable signal.

For

Unambiguous affordance; no box needed. Colour + underline reads as interactive instantly, even without the icon.

Against

Introduces a coloured, underlined value into an otherwise calm spec column — slightly breaks the "all values look alike" rhythm, and links are rarer on Android than a chip.

L3

Chip / button

Reads as a control, full stop. The value becomes a bordered toast chip ("9 languages ⓘ"). The pill shape is the clearest "this is a button" cue and gives a generous, obvious hit area.

For

No one mistakes a chip for static text. Comfortable target by construction; matches the app's other chips.

Against

Heaviest option in a narrow column — a filled pill next to plain Speed/Quality values draws a lot of attention to the least important axis, and 118 dp is tight.

L4

Chevron disclosure

"There's a list behind this." A trailing "›" (with the ⓘ leading, or on its own) frames the value as a row that opens something — the same cue a settings row uses.

For

Familiar disclosure grammar; lighter than a chip. Colour-tinting the value + chevron makes the interactivity clear without a box.

Against

A chevron usually implies full-row navigation, not a dialog — could over-promise. Two glyphs (ⓘ + ›) on a 118 dp value is busy; probably pick one.

L5

Value + "see all" hint

Spell it out. "9 languages" on top, a tiny toast "SEE ALL" caption beneath. The words do the affording; the whole stack is the target. No reliance on an icon being understood.

For

Explicit — no guessing whether it's tappable. Naturally tall, so the target is comfortable, and the hint doubles as the TalkBack action label.

Against

Adds a second line only to this one engine's Languages row, so the three engines' spec columns no longer align cleanly. Wordier than the rest.

L6

Two-letter code chips

Show the languages instead of counting them. Max's "what if" — replace "9 languages" with a wrapped row of two-letter codes. Honest catch: two-letter language codes collapse the two Englishes into one "EN" (giving 8, not 9), so this uses country codes for the pair (US / GB) and language codes for the rest — which mixes two code systems. Rendered so the mix and the wrapping are visible in the real 118 dp column.

For

Concretely shows coverage at a glance without a tap; a language you care about is either there or not. Feels information-dense and precise.

Against

Nine codes wrap to 2–3 rows in a narrow column, blowing the tidy spec alignment; codes like HI/JA/ZH aren't self-evident; and the US/GB-vs-language-code mix is a small lie. Still needs a tap to name them in full, so it doesn't remove the dialog.

L7

"ⓘ See all 9 ›"

Say the action, not the noun. Max's combined form: a leading ⓘ, the words "See all 9", and a trailing chevron. The whole value is the invitation to open the list — no ambiguity about whether it's tappable. If the double-glyph feels busy, L4 (chevron only) is the clean fallback.

For

The most unambiguous of all — it's a verb. Comfortable target, and the "9" still conveys the count. Leading ⓘ + trailing › read as "info you can open".

Against

Loses the "languages" noun, so the Languages row no longer states what the 9 are without a tap; two glyphs on a 118 dp value is visually busy (hence the L4 fallback); and it's the least like a plain spec value, breaking the column's rhythm.

What it opens (unchanged)

For reference — the dialog is the same regardless of the affordance chosen. It lists the nine locales from EngineLanguagesDialog (English US/UK count separately, which is why it's "9").

Notes for review

  • Two things to fix, independently: (1) the touch target — every option here uses negative margin so the ink position barely moves but the clickable box grows to ~44 dp; (2) the affordance — how loudly it signals "tap". They compose: e.g. L1's target size + L2's underline.
  • Icon side. Max asked for the icon on the left — all variants lead with it (or drop it, in L2/L5's plainer forms). Leading ⓘ is the "info/expand" convention.
  • Keep the column calm. Speed is meant to be the hero of the spec column; a loud Languages control (L3 chip) competes with it. L1/L2/L4 stay quieter. Weigh prominence against not over-selling the least important axis.
  • Accessibility already handled in code — the value is one Role.Button with an onClickLabel, glyph contentDescription = null so TalkBack doesn't double-announce. Only the visual affordance + hit-rect padding change here. Bumping the Row to a 48 dp min height keeps it WCAG-comfortable.
  • Only Kokoro shows this. Single-language engines render a plain "English" value (no button), so whatever wins only appears on the multi-language card — it won't clutter Kitten/Pocket.
  • Dark mode. Link/chevron use a lightened toast (--p-link) on dark so the tint stays legible; chip uses the raised container, not orange.
