## Executive summary

The codebase is in good health for a beta — threading discipline, Room migration
hygiene, ORT-footgun compliance, accessibility labeling, and the DSP chain all
checked out clean. The defects cluster in three patterns:

1. **Cross-object concurrency where the invariant lives in a comment, not a
   lock** — `release()` vs. in-flight synth, the process-global espeak behind
   per-engine wrappers, Pocket's early `env` publish.
2. **Documented behavior that was never wired up / has drifted** — the billing
   on-foreground re-verify hook, onboarding Skip, several kdoc blocks.
3. **Batched paths where streaming already exists** — both service entry points
   collect the engines' streaming flows to completion before emitting a byte.
   This is also the single biggest performance lever.

## Top 10 (correctness + perf interleaved, by impact)

1. **[CRASH] Engine `release()` can close ORT sessions mid-`session.run()`.**
   `release()` takes only `loadLock`; synthesis holds only `synthLock` — they
   never exclude each other. `EngineInstaller.uninstall()` releases **all four
   engines**, so uninstalling X while Y speaks → native SIGSEGV. Same window on
   `Synthesizer.releaseAll()` (thread-count settings change): it `cancel()`s
   then releases without awaiting synth exit. Pocket's comment
   (`PocketEngine.kt:1178-1191`) claims the guard prevents exactly this — it
   doesn't. Also: `KittenDirectEngine.kt:606-610`, `KokoroDirectEngine.kt:736-740`,
   call sites `AppModule.kt:145-149`, `EngineInstaller.kt:396,527`,
   `Synthesizer.kt:421-429`. Fix shape: release acquires synthLock then loadLock
   (or a read-write lock around session lifetime).

2. **[MONEY] Billing: the documented on-foreground `restorePurchases()` hook
   doesn't exist.** kdocs in `ProEntitlement.kt` and
   `PlayProEntitlement.kt:277-283` describe an onResume re-verify; grep finds
   `restorePurchases` called only from the two manual Restore buttons
   (`ProGateHost.kt:154`, `AboutExtras.kt:45`). Consequences: (a) a transient
   acknowledge failure after purchase is never retried → Play auto-refunds the
   user after 3 days; (b) a refunded user keeps Pro up to the 30-day cache TTL.
   Related: on ack failure `KEY_VERIFIED_AT` is never written
   (`PlayProEntitlement.kt:281-283`), so a later *offline* cold start shows a
   paying user as free.

3. **[PERF — biggest win] System TTS service is fully batched.**
   `MarmaladeTtsService.kt:393-415` → `SynthesisPipeline` → batched
   `engine.synthesize()`, which internally collects the engine's own
   `synthesizeStream` flow to completion before the first
   `callback.audioAvailable`. External apps (screen readers, ebook readers)
   hear silence for the whole synth; a 4000-char request on Pocket flirts with
   the ~10 s framework watchdog. The streaming pattern already exists and is
   proven in `Synthesizer.speak` (`Synthesizer.kt:228-235`, incl. the
   emotion≠Neutral gate and `StreamingEffectChain`). Streaming here also gives
   `onStop()` (`:427-431`, currently a stubbed no-op — finding #9) a real
   cancellation point, and kills the whole-utterance byte-duplication in
   `pcm16ToLittleEndianBytes` (`:649-676`, ~3× utterance on heap).

4. **[PERF] Long-form foreground service (share sheet / clipboard tile) is also
   fully batched.** `MarmaladeSynthService.kt:415-444` synthesizes the entire
   shared article before `playPcm` — minutes of dead air on Pocket, full PCM on
   heap (~2.9 MB/min). Adopt `Synthesizer.speakStreaming`'s producer/consumer
   channel (`Synthesizer.kt:264-319`) or inject `Synthesizer`; pause/resume
   composes via channel backpressure.

5. **[UX/TRUST] Onboarding "Skip" silently downloads the pre-selected
   engines.** `OnboardingScreen.kt:143-149` — `onSkip` calls
   `viewModel.installSelected()`; the comment claims "installs an empty set"
   but `_selectedEngineIds` initializes to all recommended engines
   (`OnboardingViewModel.kt:175-178`). A user skipping to avoid a
   multi-hundred-MB download on metered data gets it anyway, with no progress
   UI.

6. **[INSTALL] Leftover fully-downloaded archive bricks retries via HTTP 416
   loop.** `EngineInstaller.kt:637-641` — retry sends
   `Range: bytes=<partialLength>-`; if a prior attempt failed *after* download
   (e.g. disk full during extraction — the catch at `:488-505` deliberately
   keeps the archive), `partialLength == totalBytes` → 416 → hard fail in
   `UrlHttpFetcher` (`:139-141`) → every retry fails forever. Only Uninstall
   escapes. Fix: treat 416 as "download complete, skip to verify" or delete the
   archive when `partialLength == totalBytes`.

7. **[INSTALL] Reinstall/update deletes the working engine before downloading
   the new one.** `EngineInstaller.kt:392-401` deletes `finalDir` first; an
   aborted 360 MB update on flaky wifi leaves the user with *no* engine. The
   scratch-dir + atomic-rename machinery already exists — move the delete to
   after a successful download+verify.

8. **[PERF — Pocket RTF] Per-chunk voice re-conditioning (backlog #1) still
   open, still the top Pocket item.** `PocketEngine.kt:1539-1565` replays the
   voice embedding through `flow_lm_main` into fresh KV state per mini-chunk;
   PocketTTS.cpp runs it once + memcpy-restores. The needed
   `snapshotStates`/`restoreStates` machinery already exists
   (`PocketStateManager.kt:299-311`). Snapshot once per (voice, utterance),
   restore per chunk. Unblocks backlog #5 (P-V/P-Y/P-Z reattempt).

9. **[TTS CONTRACT] System/client speech rate + pitch silently ignored, and
   `onStop()` is a no-op.** `MarmaladeTtsService.kt:485` never reads
   `SynthesisRequest.getSpeechRate()`/`getPitch()` (zero refs repo-wide) —
   Android Settings speech-rate and per-app `setSpeechRate()` do nothing.
   `onStop` (`:426-431`, TODO-marked) can't interrupt a long synth (TalkBack
   stop keeps burning CPU). Both largely fall out of fixing #3.

10. **[ENGINES] espeak is process-global behind per-engine wrappers → two silent
    cross-engine bugs.**
    - Teardown: one engine's `releaseInternal()` calls `nativeClose()`
      (`espeak_jni.c:83-88,334-350`, single global `gHandle`), killing the
      *other* loaded engine's phonemizer → `phonemize()` returns null → empty
      PCM → silent no-audio until that engine reloads. Trigger:
      `BenchmarkViewModel.kt:165` releases a single engine.
    - Voice cross-talk: `setVoice(lang)` is called once per utterance outside
      `synthLock` (`KittenDirectEngine.kt:367`, `KokoroDirectEngine.kt:404`)
      and never reasserted per chunk; Kitten and Kokoro have *different* locks,
      so concurrent in-app French + system-TTS English interleaves the global
      voice → wrong-language phonemization mid-stream.
    Fix shape: a single shared espeak owner (mutex + set-voice-per-phonemize,
    refcounted teardown).

## Remaining correctness findings

### Engines / synthesis

- **Pocket publishes `env` at the *start* of load** (`PocketEngine.kt:250-257,281`)
  — first line of `doLoad` sets `env`, and `ensureModelLoaded` early-returns on
  `env != null` without the lock, so a concurrent first synth sees a half-loaded
  engine → "bundle missing after load". Kitten/Kokoro deliberately publish `env`
  **last** with a comment explaining this exact race; Pocket violates it. Also
  `env` is not `@Volatile` in any engine despite the comment claiming it is.
- **`Synthesizer.speakBatched` drops `phonemizationLanguage`**
  (`Synthesizer.kt:360`) — an alias language override is silently lost whenever
  emotion ≠ Neutral routes to the batched path. (Found independently by two
  reviewers.)
- **`Preprocessor.apply` unconditionally collapses `\s+` → " "**
  (`Preprocessor.kt:68`), so newlines never reach `preprocessForPocket`
  (P-AM newline→pause, `PocketEngine.kt:2194-2201`) or `TextChunker`'s
  paragraph splits — P-AM is dead in production and the regression it fixed is
  back.
- **`expandCurrency` throws uncaught `NumberFormatException`** on >19-digit
  amounts (`PreprocessingRules.kt:189,202-203`; contrast `expandNumber`'s
  try/catch at `:378-395`). Preprocessing runs *before* the `try` in
  `Synthesizer.speakStreaming`, escaping the Result contract → app crash on the
  in-app path (`SpeakViewModel.kt:416-430` has no handler). System-TTS path
  survives its own catch-all.
- **Pocket `releaseInternal()` leaks engine-level state buffers**
  (`PocketEngine.kt:1193-1218` nulls sessions but not
  `flowLmState`/`mimiState`/`mainSeqBuf`/`mainTextDummyBuf`) — multi-MB direct
  buffers held for process lifetime after uninstall. `flowLmState` itself is
  write-only dead weight (allocated + pinned every load, never read since the
  P-Y revert).
- **Dead experiment code confirmed still present** (all zero-caller by grep):
  P-AJ harness `runDecodeExperiment`/`decodeWithWindowPolicy`/`dumpFloats`
  (`PocketEngine.kt:2104-2168`, gate at `:2418` whose docstring says "remove
  before shipping", dead check in the hot loop at `:845`); P-Z leftover
  `runFlowLmMainAr` (`:1767-1787`); `synthesizeSingleChunk` (`:581-666`) is
  dead **and** its death breaks the benchmark's Pocket phase breakdown
  (`lastDetailedPhases` never populated); `MAX_TOKENS_PER_MINI_CHUNK` unused.
- **REPO-MAP.md still describes the vendored sherpa-onnx AAR / SherpaEngine
  architecture** — the codebase is fully direct-ORT. Stale orientation doc.

### Billing / pro (beyond #2)

- **`launchPurchase` returns Success when the Play sheet merely opened**
  (`PlayProEntitlement.kt:179-190`; the interface kdoc "returns when dismissed"
  is wrong). User cancels the sheet → paywall already self-dismissed on phantom
  Success, no error/retry shown. No false entitlement possible.
- **Custom-effect refund leak** — `DefaultEffectResolver.blocksFor`
  (`EffectResolver.kt:33-41`) has no `isPro` check; same shape as the
  `resolvePerApp` leak fixed in `ca64f4f`. Refunded user keeps custom effects
  applying at synth time indefinitely.
- **Cold-start `isPro=false` window** (`PlayProEntitlement.kt:113,148-157`) can
  skip a per-app mapping for the first utterance after process start. Low.
- F-Droid flavor verified fully free: billing is `playImplementation`-scoped,
  `FdroidProEntitlement.isPro` constant true.

### Services

- **Foreground synth service deletes its own error notification** —
  `MarmaladeSynthService.kt:425-434` posts "engine not installed"/"failed",
  then `stopIfIdle()` (`:521-528`) does `stopForeground(STOP_FOREGROUND_REMOVE)`
  on the same ID milliseconds later. Failures are effectively silent.
- **`warmUpEngine` collector leak** — `MarmaladeTtsService.kt:250-289` fires on
  every positive `onLoadLanguage`, each call launching 4 collect-forever
  coroutines on `serviceScope`. Guard with a once-flag.
- Stale comment: `MarmaladeSynthService` kdoc mentions Tasker/external callers
  but the service is `exported="false"` (behavior is the safe one).
- Verified healthy: callback start/done/error exactly-once on every path;
  PCM chunking respects `maxBufferSize`; manifest exported-component set is
  exactly the TTS contract; zip-slip guard real; all catalog URLs HTTPS;
  SHA-256 covers resumed downloads.

### Install (beyond #6/#7)

- **Per-engine install concurrency documented as caller-enforced but not
  enforced** (`EngineInstaller.kt:306-309`) — concurrent installs of the same
  engine interleave writes; SHA catches it but the failure is confusing.
- **`verify()` during an active install clobbers `Downloading` state**
  (`EngineInstaller.kt:566-577`) — `VoicePickerViewModel` probes on composition
  publish `NotInstalled` over `Downloading` momentarily; feeds the concurrency
  gap above.

### UI / data

- **"Screen re-entry unsticks ModelMissing" doesn't work**
  (`SpeakViewModel.kt:279-297`) — the VM's own `launchIn(viewModelScope)`
  collectors keep `WhileSubscribed(5_000)` permanently subscribed, so the flow
  never restarts and StateFlow won't re-emit an unchanged voice. Install engine
  → return to Speak → banner stuck until voice change/typing.
- **Cancel/re-trigger races in all three playback ViewModels**
  (`VoicePickerViewModel.kt:224-246`, `SpeakViewModel.kt:406-437`,
  `EffectEditorViewModel.kt:147-171`) — `Synthesizer.speak()` returns success
  on cancellation and superseded coroutines unconditionally write terminal
  state: preview A then quickly B → A wipes B's Playing chip; Stop-then-Speak
  re-opens the guard for concurrent synthesis. Fix: generation token per launch.
- **"Add block" picker dialog can clip lower entries**
  (`EffectEditorScreen.kt:530-556`) — 20 factories in a non-scrolling `Column`
  inside AlertDialog text; `AliasScreen.kt:572` already fixed the identical bug
  with `verticalScroll` + explanatory comment.
- **Voice-picker engine ordering is dead code**
  (`VoicePickerScreen.kt:166-168`) — `listOf("kokoro", "kitten")` never matches
  real ids (`kokoro-direct-v1_0`, …) so ordering falls to alphabetical, putting
  Kitten above the recommended Kokoro.
- **Editing a custom effect resets `createdAt`**
  (`EffectEditorViewModel.kt:184-193`) reordering the Effects list; contrast
  `AliasViewModel.save()` which preserves it.
- Low/notes: stale-snapshot guards in `AliasViewModel.kt:351,419` (pre-first-
  emission window); stale `EngineCardState.isSelected`
  (`OnboardingViewModel.kt:194-198`) + kdoc drift; theme-preset chip row uses a
  non-wrapping `Row` with a stale "FlowRow is experimental" comment while the
  same file uses FlowRow twice (`SettingsScreen.kt:242-258`); one engine's
  ModelMissing disables Preview on all rows (`VoicePickerScreen.kt:93-94,196`);
  `fallbackToDestructiveMigration()` (`AppModule.kt:70-71`) will silently wipe
  user data on any future missed migration — reconsider before 1.0; unused
  imports + stale copy ("Open the Engines tab") noted in report.

## Remaining performance findings

(#3, #4, #8 above are Tier 1.)

- **TTFA: exempt chunk 0 from the `minChars` merge** —
  `KokoroDirectEngine.kt:407-414,776` / `KittenDirectEngine.kt:377-384,640` /
  `TextChunker.kt:132-151`: `mergeUpToMin` fattens the first chunk to ≥80 chars;
  first-infer time scales with chunk length and later chunks pipeline anyway.
  Emit the first natural sentence alone. Risk: Kitten short-utterance prosody
  (style row indexes text length) — listen-test chunk 0.
- **Pocket per-chunk flow_lm state alloc + scalar NaN fill** —
  `PocketEngine.kt:1534` allocates ~18 direct buffers per mini-chunk (P-Y
  revert); `PocketStateManager.kt:437-459` fills them one float at a time.
  (a) low-risk: bulk-`put` from a lazily-built constant template buffer (also
  helps the 56-slot mimi `resetStatesToInit`, `PocketEngine.kt:788,897`);
  (b) medium-risk: 2-deep state-map pool, must be A/B'd on device (P-Y bisect
  history).
- **Pocket decode pipelining gated to preroll K>1** (`PocketEngine.kt:891`,
  loop order `:826-913`) — at K=1 each chunk's mimi decode runs synchronously
  between AR loops. Emitting from the async decode completion would overlap
  decode(N) with AR(N+1) without delaying chunk 0.
- **Pocket per-batch snapshot allocations** — `PocketEngine.kt:2065` →
  `PocketStateSlot.snapshot()` (`PocketStateManager.kt:263-272`) allocates 56
  fresh ByteArrays per 64-frame batch. Persistent per-slot snapshot buffers.
- **Kitten micro-wins** — port Kokoro's `styleScratchBuf` pattern
  (`KokoroDirectEngine.kt:214-219,276-279`) to Kitten
  (`KittenDirectEngine.kt:450,468,520-527`); cap+reuse a 502-long token scratch
  in both engines.
- **UI**: main-thread `pm.getApplicationIcon` + bitmap rasterization per visible
  row (`AppMappingsScreen.kt:516-524,560-578` — move into `Dispatchers.IO`
  inside the producer); eager Drawable retention for every launchable app in
  the picker VM (`AppMappingsViewModel.kt:185-216`, contradicts its own kdoc);
  `remember(voices)` the group/sort in `VoicePickerScreen.kt:163-168`;
  `produceState`+IO the license asset read in `LicensesScreen.kt`.
- **Micro**: hoist `Regex("\\s+")` in `Preprocessor.kt:68` +
  `EmojiProsody.kt:166`; `StreamingEffectChain.kt:45-48` per-stage array churn
  (biquad/vol/overdrive can process in place).
- **Execution providers**: session options already well tuned (XNNPACK,
  ALL_OPT, mmap on arm64, per-device threads). NNAPI not recommended
  (dynamic-shape sequence models partition poorly). FP16 levers are model-side
  (Pocket fp16 KV re-export; Kokoro fp16 variant) and fold into the ExecuTorch
  strategic path — the architectural wins above survive that runtime swap.
